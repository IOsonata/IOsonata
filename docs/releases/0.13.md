# IOsonata 0.13: release preparation

Status: preparation on `release_0.13`; this document does not announce a
published release.

## Changes since 0.12

0.12 introduced early USB device/CDC support. 0.13 expands the device stack
with composable CDC, custom Bulk, HID, MSC and Bluetooth HCI USB functions,
plus reusable Interrupt and Isochronous transports.

- Interface and endpoint allocation is internal to the stack. Device classes
  register descriptor fragments or builders with the common USB core.
- `UsbIntrf` supplies the shared endpoint-pair data path. Nordic USB changes
  consolidate DMA scheduling, interrupt completion, reset and reconnect handling.
- The nRF54LM20x USBHS port supports full-speed and high-speed device operation,
  EP0, CDC, HID, MSC, bulk, interrupt and ISO transfers. Bare-metal and TaktOS
  composite examples have passing 2,000-second hardware runs. See the
  [LM20 port notes](../usb-nrf54lm20x.md) for supported projects and limits.
  nRF54L15 has no USB peripheral; nRF54H20 needs its separate power backend and
  is not covered by the LM20 USB hardware results.
- Examples cover individual functions, dual CDC and simultaneous CDC/HID/INT/ISO
  stress. TinyUSB examples provide a baseline using the same IOsonata platform
  library and host runners.
- USB storage and constructor changes reduce initialized data. nRF52840
  configuration-descriptor capacity is now 768 bytes.
- Bluetooth memory work makes connection, security and other optional features
  link only when referenced on the updated ports. Platform changes also reduce
  unused timer, GPIO and storage dependencies.
- nRF91 series Bluetooth: the generic host runs on the nRF9160 and nRF91x1
  libraries over an H4 HCI UART transport (`BtHciUart`) to an nRF5x running
  HciController. Security is not supported on this port yet. See the
  [Bluetooth User Guide](../bluetooth-user-guide.md#hci-over-uart-nrf91).
- Nordic UARTE DMA receive no longer loses the end of a transfer that crosses
  the end of the RX FIFO memory, and waits for FIFO room before receiving
  more, so hardware flow control holds the sender off instead of bytes being
  dropped.

The final memory work is included in
[PR 63](https://github.com/IOsonata/IOsonata/pull/63), and HCI/MSC constructor
changes in [PR 64](https://github.com/IOsonata/IOsonata/pull/64).
HCI and MSC are both included in the release-preparation base.

## Migrating applications

Rebuild the affected MCU library, then clean and rebuild applications using
the same headers and build configuration. USB configuration and object layouts
changed; do not mix an older library with new headers.

### HID and Interrupt buffers

`UsbdHidCfg_t` and `UsbIntIntrfCfg_t` now require caller-owned `pRxBuffer`
and `pTxBuffer`. Each slot must be 4-byte aligned, contain at least
`USB_INT_INTRF_PKT_BLKSIZE` bytes and remain alive for the interface lifetime.
Use separate static arrays as shown in
[usb_hid_loopback.cpp](../../exemples/usb/usb_hid_loopback.cpp) and the
[USB User Guide](../usb-user-guide.md).

### USB composition and startup

Initialize the core, initialize every class successfully, then enable USB and
run the application event queue. Stop startup if a class initialization
fails.

### One event queue for every subsystem

The application owns the main loop. USB and Bluetooth hand their deferred
work to `UsbEvtQue()` and `BtEvtQue()`; the library defaults put it in the
application event queue, which only the application runs, first in first
out, with the new `AppRun()` or `AppEvtHandlerExec()` in its own loop. No
subsystem runs the queue or owns a loop.

- `BtAppRun()`, `BtAppEvtWait()`, `BtAppEvtNotify()` and
  `BtAppEvtDispatch()` are removed. Replace `BtAppRun()` with `AppRun()`.
  `BtAppInit()` starts advertising itself.
- The nRF52 application path uses AppEvt only. `BtAppInit()` no longer
  initializes the SDK scheduler; `BtAppSchedCfg_t` and `g_BtAppSchedCfg`
  are removed. Remove those overrides and migrate application
  `app_sched_event_put()` calls to `AppEvtHandlerQue()` or `BtEvtQue()`.
  AppEvt stores a context pointer rather than copying event data, so that
  context must remain valid until the callback runs. SDK-only applications
  with their own scheduler initialization and loop remain separate.
- The application no longer calls `UsbProcess()`. The USB stack queues its
  process event after controller and endpoint events.
- `AppEvtHandlerExec()` returns `true` when events are still waiting.
- `AppRun()` drains the queue, then calls `AppCheckStatus()` when it is empty.
  A `true` return means idle; the loop sleeps only if no event is waiting.
  The default hook calls the linked USB and Bluetooth status checks. An
  application override calls its subsystem checks and retries its retained
  work, returning `false` while work remains. AppEvt also invokes this hook
  after a queue refusal when the queue becomes empty; it does not store the
  refused callback or copy its context data.
- The queue defaults to 4 events. An application needing more defines
  `g_AppEvtHandlerQueMem` and passes its size to `AppEvtHandlerInit()`.
  Neither `UsbInit()` nor `BtAppInit()` sizes it.
- `BtAppCfg_t` no longer has `pEvtHandlerQueMem` and `EvtHandlerQueMemSize`:
  the queue belongs to the application and `BtAppInit()` does not touch it.
  An application that set them calls `AppEvtHandlerInit()` itself. With an
  RTOS that overrides `BtEvtQue()`, the queue is no longer linked.
- With an RTOS, override `UsbEvtQue()` and `BtEvtQue()` to send the work as a
  message to the subsystem thread, which runs it. Before blocking, each worker
  calls its subsystem status check and retries any retained application work.
  See the TaktOS and FreeRTOS examples.

On nRF52 and nRF54LM20, regular endpoint completion and OUT readiness callbacks
run in the USB interrupt. On nRF52, IN DMA END releases EasyDMA, while EPDATA
reports host consumption before the owner releases or reuses the TX data.
OUT END retires DMA and starts queued work, then calls the completed endpoint
owner before handling its next readiness. On LM20, a completed endpoint is
idle before its owner is called. Application callbacks must account for this
interrupt context even when their application uses an RTOS.

The UART/BLE and USB/BLE examples retain refused work until its callback runs.
The bridge FIFOs publish data after filling reserved spans and release spans
after copying them. UART central keeps its data until `BtAppWrite()` accepts
the write. The UART/BLE RTOS examples use `BtAppInitUserServices()` and
`BtAppInitUserData()` and let the port dispatch GATT events once.

Custom classes should follow the current `UsbDeviceClass` registration and
`UsbIntrf` transport model in the [USB architecture](../architecture/usb.md).
Do not copy endpoint numbers or callback-registration code from the earlier
USB implementation.

The nRF52840 default configuration buffer is 768 bytes. Larger custom
configurations must override `USB_CONFIG_DESC_MAXLEN` when building the MCU
library. Application-only defines cannot resize the precompiled core.

CDC, HID, HCI and MSC use out-of-line constructors. Custom startup code must
execute normal C++ static constructors before application initialization.

### Bluetooth feature selection

On ports implementing the opt-in security model, applications using pairing
or bonding call `BtAppSecInit()` from `BtAppInitUserData()`. Selecting a
non-NONE `SecType` without initializing security makes `BtAppInit()` fail.
See [bt_app.h](../../include/bluetooth/bt_app.h) for the port-specific contract.

Adding a GATT service or initiating a connection starts connection support on
ports implementing `BtAppConnInit()`. A peripheral that must be connectable
without any service calls it from `BtAppInitUserServices()`. Advertising-only
and scanning-only applications can omit connection support. These linking
changes do not imply identical memory savings on every Bluetooth port.

## SAM4L USB port

The SAM4L USBC device port now provides native EP0, bulk and interrupt DMA
through the existing USB/core/UsbIntrf callbacks. The SAM4LCxC library and
SAM4L8 Xplained Pro CDC loopback projects include bare-metal and TaktOS builds.
`MCUOSC` enables the USB generic clock in `SystemInit()`; PC11 provides cable
sense. SAM4L GPIO dispatch now covers all twelve eight-pin interrupt groups.
ISO and host operation remain disabled, and the full combo workload exceeds
the controller's physical endpoint capacity. Debug/Release compile/link and
host register-model checks pass; board testing is pending. See the
[SAM4L section of the USB user guide](../usb-user-guide.md#sam4l).

## Before tagging

Clean-build the selected release libraries and examples from the final release
commit, including the corrected UART/BLE and USB/BLE examples, and verify their
basic traffic on hardware. Record compiler, firmware revision, board and host
setup with results. The four composite endurance runs above are complete;
repeat affected hardware checks if subsequent firmware changes alter those
paths. Complete HCI integration testing in HciController and record the
results. Preserve the MSC confirmation in the published notes.

DFU hardware testing and further size/performance optimization remain deferred
to a later release. H20 USB integration is outside the LM20 support claimed here.
