# nPM1300 driver

`PmnPM1300` uses the IOsonata `PowerMgnt`, `FuelGauge` and `DeviceIntrf` interfaces. The non-destructive `Init(DeviceIntrf *)` path only probes the PMIC. The full `PwrMgntCfg_t` initializer applies only the regulator, charger and interrupt settings requested by the configuration.

## Supported functions

- BUCK1/BUCK2 normal and retention voltage from 1.0 V to 3.3 V in 100 mV steps, software enable/disable, forced PWM, forced PFM, active discharge and status.
- LDO1/LDO2 voltage from 1.0 V to 3.3 V, load-switch mode, enable/disable, 25/50/75/100 mA soft start, active discharge and status.
- GPIO mode, pull-up/down, open-drain, drive strength and input status.
- Charger current from 32 mA through 800 mA. Hardware resolution is 2 mA; odd requests are rounded down to the next supported value and `SetCharge()` returns the actual current.
- Normal and warm termination voltage at 3.50-3.65 V or 4.00-4.45 V in 50 mV steps, 10/20 percent termination current, 2.5/2.9 V trickle threshold, automatic recharge, NTC protection, warm/cool charge policy, 200/1000 mA battery discharge limit and VBUS input-current limit.
- Charger error/status access, charger error release/clear, safety-timer clear and ERRLOG access.
- Fresh single-shot VBAT and NTC ADC measurements. The driver clears the ready event before each conversion, waits for the matching ready event and rejects bus failures, timeouts and invalid NTC endpoint codes.
- Interrupt masks for events represented by the generic power-management callback: charge complete, VBUS detected and thermal/NTC over-temperature. Unsupported battery-detect events are not enabled.
- Full PMIC reset and guarded ship-mode entry. Ship mode is rejected while VBUS is present.

The nPM1300 interrupt output is a PMIC GPIO selection and therefore belongs to board setup. Configure the selected PMIC GPIO with `SetGpioMode(..., NPM1300_GPIOS_GPIOMODE_GPOIRQ)`. Thingy:91 X uses nPM1300 GPIO3.

## Battery state and state of charge

Battery detection is disabled on D00 and later nPM1300 silicon (PCN213), so the BATTERYDETECTED status and BATDETECTED/BATLOST events cannot be used for physical battery-presence reporting on current production parts. `BatteryState()` therefore returns `PWRMGNT_BATTERY_UNKNOWN`; the legacy Boolean `Battery()` returns false meaning only that presence is not confirmed.

The PMIC does not provide a calibrated state-of-charge percentage. IOsonata has device-specific fuel-gauge support and an old Thingy:52 voltage lookup, but no generic battery-model/coulomb estimator suitable for nPM1300. `Level()` returns `UINT16_MAX`. A battery-specific model with characterized charge/discharge data and current integration is required before a percentage can be reported.

## Configuration limits

`PwrMgntCfg_t::ChrgTimeout` is rejected when nonzero. The exposed nPM1300 charger interface can clear its safety timers but this driver does not invent a programmable timeout that is not represented by the silicon interface.

VBUS removal returns the nPM1300 to its startup input-current limit. When `SetInputCurrentLimit()` has been used and VBUS-detected interrupts are enabled, the interrupt handler reapplies the host-selected limit on reconnect.

## Software validation

`tests/pwrmgnt/npm1300_test.cpp` compiles and executes the production `src/pwrmgnt/pm_npm1300.cpp` against a simulated `DeviceIntrf`. Coverage includes initialization failures, BUCK/LDO boundaries, load switches/GPIO, charger encodings, ADC readiness and numerical limits, interrupt masking/clearing, status/fault reads, read/write failures, unsupported battery reporting and ship-mode safeguards.

Run:

```sh
python3 tests/pwrmgnt/run_npm1300.py
```

The host test is built at `-O0` and `-O2` with `-Wall -Wextra -Werror -Wpedantic` and ASan/UBSan. Thingy:91 X build/test project: `ARM/Nordic/nRF91/nRF91x1/exemples/nPM1300Test`. Physical nPM1300 validation is still required.
