# 0.13 MCU target-build verification

This is the native IOcomposer/Embedded CDT firmware-build gate. The host CI
does **not** replace it. No clean target-build result is claimed by this file.

## Baseline and evidence

Check out `release_0_13_final_prep` with its matching IOsonata, TaktOS and
external SDK repositories. Record the exact commit, GCC version, operating
system, library archive path, application ELF path and console/log evidence
for every tested configuration. Do not change linker scripts, project files
or source during validation without committing the correction and rerunning.

## Native execution procedure

1. Launch the installed IOcomposer with configured Arm/RISC-V toolchain paths.
2. Import the MCU library's `ioc` project (and the required TaktOS library
   project when applicable).
3. Select Debug and perform a clean build of the library; inspect compiler
   errors, generated archive and resolved source/library paths.
4. Import the application `ioc` project, select Debug and clean-build it;
   verify that the ELF links with the matching library configuration.
5. Repeat the library-then-application sequence with Release.
6. Save the full build logs and artifact sizes; confirm no stale archive/ELF
   was accepted as a new build. Record results against the exact Git commit.

An automated headless run may use
`org.eclipse.cdt.managedbuilder.core.headlessbuild` with a **fresh**
workspace, `-import` for both projects and `-cleanBuild` of the explicit
`project/configuration`. Do not use a successful process exit alone as
proof: verify logs and newly generated outputs in both configurations.
