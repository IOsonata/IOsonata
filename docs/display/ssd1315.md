# SSD1315 monochrome OLED

`LcdSSD1315` in `display/display_ssd1315.h` implements the IOsonata
`DisplayDotMatrix` interface over an initialized `DeviceIntrf` SPI object.
The driver is independent of the MCU. It owns a fixed 1,024-byte framebuffer
and uses no heap storage. Add `src/display/display_ssd1315.cpp` to the target
library project when using it on another MCU.

## Configuration and use

Use four-wire SPI, mode 0, eight-bit words, MSB first, polling with interrupts
and DMA disabled. In IOsonata this is `SPICLKPOL_HIGH` (active high, CPOL=0,
idle low) with `SPIDATAPHASE_FIRST_CLK` (CPHA=0). The driver uses
`StartTx` / `TxData` / `StopTx` and checks
the returned byte count. It does not change the SPI controller configuration.
The chip-select index is `DisplayCfg_t::DevAddr`.

Set `PixelSize` to 1, `Width` to the native panel width (up to 128), `Height`
to the native panel height (16 through 64, a multiple of eight), and `Stride`
to `(Width + 7) / 8`. Initialization uses the internal 7.5 V charge pump;
panels requiring an external OLED supply need a different power setup.
The default contrast is 127; `Contrast()` sets the eight-bit contrast value.

`pPins[DISPL_CTRL_DCX_PINIDX]` is the required D/C output.
`pPins[DISPL_CTRL_RST_PINIDX]` is an optional active-low reset output.
Keep the unused backlight entry at index 1 with port/pin -1. It is never
configured or driven. With no reset pin, provide only the D/C entry, or
set the reset entry's port/pin to -1.

```cpp
static LcdSSD1315 display;
// spi has already been initialized; cfg and its pin array remain valid.
if (display.Init(cfg, &spi)) {
    display.SetCursor(0, 0);
    display.printf("IOsonata\nSSD1315 OLED");
    display.Fill(0, 24, 128, 1, 1);
}
```

The standard `Clear`, `Fill`, `SetPixel`, `BitBlt`, `Scroll`, `Orientation`,
`SetFont` and `printf` methods are supported. Drawing updates the panel
immediately. Zero means black and any nonzero color means white. Bounds
are clipped; a clipped bitmap retains its original source row stride.
`BitBlt` accepts packed monochrome rows, MSB first, padded to whole bytes.
This differs from color displays, which accept whole color pixels.

Use the display's `printf` for text. It supports the existing internal
fixed vertical, fixed horizontal and variable-width IOsonata fonts, with
the default `iFontSystem5x7`. The font tables start at ASCII '!'; space is
handled separately and unsupported text bytes render as '?'.
`SetCursor` selects the top-left pixel of the next character. Text wraps
and scrolls upward at the bottom. External fonts and glyph-format fonts
are not supported. The separate `iGfx::Print` color-pixel renderer is not
used by this driver; `iGfx` line drawing can use its `SetPixel` and `Fill`.

All four orientations map drawing coordinates in software. Portrait
orientations exchange the logical width and height; changing orientation
keeps the physical framebuffer and resets the text cursor. `Scroll` shifts
in logical coordinates and clears newly exposed pixels. `Disable` turns
off the display and charge pump while retaining the framebuffer;
`Enable` resumes it. `Reset` reapplies the setup and clears the display.

`Init`, `Refresh`, `Enable` and `Contrast` report transfer failure. The
inherited drawing methods return void; after a bus failure, `Refresh`
retries the full framebuffer without rebuilding the image. `Valid()`
records whether the last initialization/reset succeeded. Use one owner
for a display object; simultaneous drawing calls are not serialized.

## STM32WBA65I-DK1 example

Import `ARM/ST/STM32WBAxx/STM32WBA65/exemples/LCDConsoleDisplayDemo/ioc` and rebuild
`IOsonata_STM32WBA65` in the matching Debug or Release configuration.
The library project includes the new driver source. The example uses
the existing `exemples/display/console_display_demo.cpp` and requires no jumper wires.

| Signal | Pin | Function |
|---|---|---|
| Clock | PA0 | SPI3 SCK, AF6 |
| Data | PB8 | SPI3 MOSI, AF6 |
| Chip select | PE1 | GPIO |
| Data/command | PE0 | GPIO |
| Reset | PE3 | GPIO |

SPI3 is IOsonata DevNo 2. MISO is unused. Remove external SPI loopback
jumpers or shields sharing these pins; PA0 also appears on Arduino A5.
The screen cycles through the existing font samples, scrolls text and rotates
through the four orientations. Fonts that do not fit the current panel size
are skipped. The board selects the SSD1315 and its geometry; the shared demo
keeps its existing HX8357 defaults for other boards.

## Validation

Run `python3 tests/display/run_ssd1315.py` with GCC and sanitizers installed.
The test uses the production display, device and interface implementations
and a modeled SPI controller. It checks command/data selection, initialization
commands, page RAM, preservation of neighboring pixels, clipped bitmaps,
four rotations, scrolling, font output, failed transfers and subsequent retry.
It runs at `-O0` and `-Os` with AddressSanitizer and UndefinedBehaviorSanitizer.

The WBA65 driver and example compile and link in Debug and Release with
Arm GCC 13.2.1. OLED operation on the board still needs verification.
