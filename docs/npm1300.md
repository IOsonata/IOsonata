# nPM1300 driver

`PmnPM1300` uses the IOsonata `PowerMgnt`, `FuelGauge` and `DeviceIntrf` interfaces. The non-destructive `Init(DeviceIntrf *)` path only probes the PMIC. The full `PwrMgntCfg_t` initializer applies only the regulator, charger and interrupt settings requested by the configuration.

## Supported functions

- BUCK1/BUCK2 normal and retention voltage from 1.0 V to 3.3 V in 100 mV steps, software enable/disable, forced PWM, forced PFM, active discharge and status. BUCK enable, retention and PWM control can be routed to any nPM1300 GPIO with selectable polarity.
- LDO1/LDO2 voltage from 1.0 V to 3.3 V, load-switch mode, enable/disable, GPIO enable routing, 25/50/75/100 mA soft start, active discharge and status.
- GPIO mode, pull-up/down, open-drain, drive strength and input status.
- Charger current from 32 mA through 800 mA. Hardware resolution is 2 mA; odd requests are rounded down to the next supported value and `SetCharge()` returns the actual current.
- Normal and warm termination voltage at 3.50-3.65 V or 4.00-4.45 V in 50 mV steps, 10/20 percent termination current, 2.5/2.9 V trickle threshold, automatic recharge, NTC protection, warm/cool charge policy, 200/1000 mA battery discharge limit and VBUS input-current limit.
- Charger error/status access, charger error release/clear, safety-timer clear and ERRLOG access.
- Fresh single-shot VBAT, signed IBAT and NTC ADC measurements. The driver clears the ready event before each conversion, waits for the matching ready event and rejects bus failures, timeouts and invalid NTC endpoint codes.
- Interrupt masks for events represented by the generic power-management callback: charge complete, VBUS detected and thermal/NTC over-temperature. Unsupported battery-detect events are not enabled.
- Full PMIC reset and guarded ship-mode entry. Ship mode is rejected while VBUS is present.

The nPM1300 interrupt output and regulator GPIO routing belong to board setup. Configure the selected interrupt GPIO with `SetGpioMode(..., NPM1300_GPIOS_GPIOMODE_GPOIRQ)`; `SetBuckEnableGpio()`, `SetBuckRetentionGpio()`, `SetBuckPwmGpio()` and `SetLoadSwitchEnableGpio()` configure hardware-controlled rail inputs. Passing GPIO index `-1` disconnects the corresponding hardware control. Thingy:91 X uses nPM1300 GPIO3 for IRQ and GPIO2 as the active-high BUCK2 enable input.

## Battery state and state of charge

Battery detection is disabled on D00 and later nPM1300 silicon (PCN213), so the BATTERYDETECTED status and BATDETECTED/BATLOST events cannot be used for physical battery-presence reporting on current production parts. `BatteryState()` therefore returns `PWRMGNT_BATTERY_UNKNOWN`; the legacy Boolean `Battery()` returns false meaning only that presence is not confirmed.

The PMIC measures voltage, current and temperature; state of charge is calculated on the host. `PmnPM1300` remains independent of an algorithm library and returns `UINT16_MAX` from `Level()`. The optional `PmnPM1300FuelGauge` class adds Nordic's secondary-cell algorithm through the existing `FuelGauge` interface. Its `Level()` reports tenths of a percent, or `UINT16_MAX` before initialization and after a failed update. `Current()` reports microamps, positive for discharge and negative for charge; `INT32_MIN` means unavailable. `ReadBatterySample()` publishes a sample only when all measurements and charger settings were read successfully.

Application measurements use `FuelGauge::Level()`, `Voltage()` and `Temperature()`;
charger and regulator control use `PowerMgnt`. Both capabilities share the same
`Device` and injected `DeviceIntrf`. The optional adapter contains the Nordic
algorithm calls and translates its floating-point percentage to the generic
fixed-point level. The generic headers and PMIC register driver do not depend on
the SDK. Model selection, estimator scheduling and persistence remain optional
adapter operations; no MCU-specific bus calls are required by the application.

### Model-based fuel gauge

The Nordic fuel-gauge library can run on non-Nordic MCUs with a supported CPU architecture and ABI. Its location in sdk-nrfxlib does not require an nRF MCU, Zephyr or the rest of the SDK. This adapter uses the v3.2.0 API; select a matching archive for the target CPU, floating-point ABI and toolchain. Availability of archives differs between releases, so the supplied nRF9120 archive path must be changed for another target. See [Nordic bare-metal PMIC integration](https://www.nordicsemi.com/Products/PMIC-software-and-tools/Bare-metal-Developer). The PMIC register driver remains independent of this optional algorithm library.

- Compile `src/pwrmgnt/pm_npm1300_fuel.cpp` in the application. It is optional and is not added to every IOsonata library.
- Use the **sdk-nrfxlib v3.2.0** secondary-cell fuel-gauge header and matching archive together. Include `external/sdk-nrfxlib/nrf_fuel_gauge/include` and link `lib/cortex-m33/hard-float/libnrf_fuel_gauge.a` for the nRF9120 project. The example contains these paths. A newer incompatible Nordic API requires an adapter update; do not mix headers and archives from different releases.
- Initialize the PMIC with `FuelGaugeCfg_t` to supply the thermistor profile, then call `StartFuelGauge(model, monotonicMilliseconds)`. Call `UpdateFuelGauge(monotonicMilliseconds)` regularly (the example uses one second). Real elapsed time, including sleep, is required. Unsigned millisecond rollover is supported; updates must be less than 2^31 milliseconds apart.
- `nPM1300Test` uses Nordic's characterized LP803448 model from [Asset-Tracker-Template](https://github.com/nrfconnect/Asset-Tracker-Template/blob/main/app/src/common/lp803448_model.h), retained under its original Nordic license beside the model. This model is for the stock Thingy:91 X battery. A replacement cell needs its own characterized model. The model must remain valid for the lifetime of the gauge.
- Voltage, current, temperature, VBUS state, charge state, charge-current limit and termination current are supplied to the algorithm. Failed I2C transfers, ADC timeouts, invalid current status and invalid SOC invalidate the reported level. No voltage-only percentage or fabricated zero-current sample is used.
- `TimeToEmpty()` and `TimeToFull()` return seconds, or NaN when unavailable. The configured `FuelGauge` low-battery callback runs once on crossing 10 percent, and rearms at 15 percent.
- `FuelGaugeIdle()` supplies a known average discharge current before a low-power interval. Continue updates with actual elapsed time after waking. The application owns persistence: use `FuelGaugeStateSize()` and `SaveFuelGaugeState()` with caller-owned storage, and optionally restore that state at startup. Restore only with the same battery model, library version and firmware addresses; discard state after a battery replacement or incompatible firmware change.
- The Nordic library has one global algorithm state. Only one adapter can own it at a time. Use one application context, never an interrupt handler. Reset, reinitialization and successful ship-mode entry invalidate the adapter's state.

The estimator cannot restore the silicon's disabled battery-presence detection. `BatteryState()` remains unknown independently of whether an SOC estimate is available.

## Configuration limits

`PwrMgntCfg_t::ChrgTimeout` is rejected when nonzero. The exposed nPM1300 charger interface can clear its safety timers but this driver does not invent a programmable timeout that is not represented by the silicon interface.

VBUS removal returns the nPM1300 to its startup input-current limit. When `SetInputCurrentLimit()` has been used and VBUS-detected interrupts are enabled, the interrupt handler reapplies the host-selected limit on reconnect.

## Software validation

`tests/pwrmgnt/npm1300_test.cpp` compiles and executes the production `src/pwrmgnt/pm_npm1300.cpp` against a simulated `DeviceIntrf`. Coverage includes initialization failures, BUCK/LDO boundaries, load switches/GPIO, charger encodings, ADC readiness and numerical limits, interrupt masking/clearing, status/fault reads, read/write failures, unsupported battery reporting and ship-mode safeguards. The optional adapter is exercised with an algorithm mock for unit conversion, timestamps and rollover, failure propagation, saved-state buffers, single-owner enforcement, low-battery callbacks and lifecycle. These tests do not validate the Nordic estimation algorithm or battery accuracy.

Run:

```sh
python3 tests/pwrmgnt/run_npm1300.py
```

The host test is built at `-O0` and `-O2` with `-Wall -Wextra -Werror -Wpedantic` and ASan/UBSan. Thingy:91 X application-level power routing is shared by the nPM1300, nPM6001 and BME688 tests through `ARM/Nordic/nRF91/nRF91x1/exemples/common/thingy91x_board.*`. Thingy:91 X build/test project: `ARM/Nordic/nRF91/nRF91x1/exemples/nPM1300Test`. Physical nPM1300 validation is still required.
