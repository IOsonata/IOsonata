# IOsonata 0.13

IOsonata 0.13 completes the USB device stack introduced in 0.12 and expands Bluetooth, internal-flash storage, firmware updating, networking and MCU support. The release retains the IOsonata Object Framework and Eclipse Embedded CDT managed-project workflow.

## Highlights

- **Composable USB device stack:** CDC, custom bulk, HID, MSC and Bluetooth HCI functions, with interrupt and isochronous endpoints. Composite USB supports multiple functions in one device without application-authored USB descriptors.
- **USB MSC using internal MCU flash:** A new nRF52840 flash-disk example exports linker-reserved program flash as a USB drive. Generic `Nvm` and `NvmDiskIO` provide the storage path, while FatFs is optional for firmware-side file access.
- **Firmware updates:** Signed nRF52840/S140 USB recovery and BLE firmware update flows, with downgrade protection and recovery procedures.
- **Bluetooth and NVM coexistence:** Flash access is arbitrated through S132 SoftDevice or SDC/MPSL timeslots while advertising continues.
- **Network services:** Shared `SockIntrf` networking with lwIP/Ethernet, TLS 1.3, MQTT 3.1.1, CoAP and a new HTTP server example.
- **More MCU ports:** RA4M1, LPC11U35/LPC1769/LPC54628, SAM D11/D21, SAM4LS, STM32F030x8 and initial STM32L152RE; STM32WBA65 adds Bluetooth support.
- **Smaller dependencies:** Generic NVM no longer pulls in Nordic QSPI or other QSPI controller implementations when the application does not use them.

## USB device and storage

USB classes register their descriptor fragments with the shared USB core, which allocates interfaces and endpoints. `UsbIntrf` provides the common data path. Examples include CDC, HID, custom bulk, MSC, dual CDC and composite CDC/HID/interrupt/ISO applications, with bare-metal and TaktOS variants.

USB device ports cover nRF52840, nRF54LM20 (full and high speed), SAM4L, RA4M1, STM32L4, STM32H753, STM32WBA65, LPC11U35, LPC1769, LPC54628 (USB1 high speed) and SAM D11/D21.

The nRF52840 **UsbMscFlashDisk** example uses internal program flash as block storage. It presents 512-byte USB logical sectors over native 4096-byte erase pages, using a single caller-owned erase-page cache. It supports first-use FAT12 provisioning, synchronization and eject handling, and persistent host file operations. Cache flush failures propagate to the caller. The example does not provide wear leveling or power-failure atomicity, and host and firmware must not write the same filesystem concurrently without coordination.

Generic NVM supports medium-specific erase and write geometry. QSPI updates correct Nordic custom-command opcode handling and parameter bounds, and decouple phased command and flash-size operations from globally linked QSPI functions. These are targeted safety and link-size changes, **not** a claim that the entire QSPI transaction API has been redesigned.

## Bluetooth

- Nordic SoftDevice and SDC: advertising, central and peripheral operation, security, pairing, bonding and portable HCI host integration.
- A common application event queue serves USB and Bluetooth. `AppRun()` replaces `BtAppRun()`.
- Connection and security code link only when used. Pairing/bonding applications initialize security through `BtAppSecInit()`.
- Generic PHY and data-length control through `BtGapSetPhy()`, `BtGapReadPhy()` and `BtGapSetDataLength()` on the HCI, Nordic SoftDevice and STM32WBA ports.
- `TxPower` uses dBm consistently, including 0 for 0 dBm.
- Nordic SDC central notification and connection improvements, and STM32WBA65 Bluetooth support using the ST host and Basic Plus link layer.
- `BleNvmStress` demonstrates flash operation and BLE advertising coexistence: nRF52832 hardware tests completed under both S132 SoftDevice and SDC, with all flash operations handled by the corresponding arbiter rather than direct NVMC access. The application-specific S132 stress-test flash reservation is not suitable for a board with an overlapping bootloader.

## Firmware updates

The nRF52840/S140 examples support signed firmware updates through **USB recovery** and **BLE upload/installation**. Hardware testing covered recovery, BLE installation, downgrade rejection, and retry after an interrupted BLE upload. The bootloader's behavior during power loss in the middle of the firmware-copy stage has not been fully hardware-qualified.

See the [firmware update user guide](https://github.com/IOsonata/IOsonata/blob/0.13/docs/dfu-user-guide.md) for signing, provisioning and update instructions.

## Networking

`SockIntrf` unifies socket operations across supported backends, including Ethernet/lwIP and nRF91 modem sockets. Networking examples cover TCP/UDP, TLS, MQTT and CoAP. A new reusable HTTP server and Eclipse managed Ethernet HTTP server projects target LPC54628 and STM32H753.

## MCU and peripheral support

- **Renesas RA4M1:** startup, GPIO/ICU, UART with TX DMA, timers, I2C, SPI, USB device and SCE5 crypto.
- **NXP LPC11U35, LPC1769, LPC54628:** startup, GPIO, UART, timers, I2C/SPI masters and USB device. LPC54628 also has DMA, Flexcomm I2C/SPI master/slave, RTC, ADC, PWM, SPIFI, SDRAM, SD card, I2S audio, LCD/touch and Ethernet.
- **Microchip SAM D11/D21:** UART, timers, I2C, SPI, DMA, USB device, ADC and DAC. **SAM4L:** I2C/SPI master/slave and USB device, with SAM4LS library support.
- **STM32:** shared GPIO, UART and timer drivers across families; improvements for STM32L4, F030x8 and initial L152RE ports; STM32WBA65 USB/Bluetooth.
- **Nordic:** nRF54L15/LM20 I2C and SPI, nRF91 SPIM/TWIM interrupt mode and UARTE DMA receive fixes. nRF54H20 support remains compile-only.

The installer provisions the project dependencies and tools. Projects use Eclipse Embedded CDT managed builds, with a standardized linker-script layout and reserved NVM regions.

## Upgrading from 0.12

- **Rebuild MCU libraries**, then clean and rebuild applications with the matching 0.13 headers. USB object layouts changed; do not mix old libraries with new headers.
- Replace `BtAppRun()` with `AppRun()`. `BtAppEvtWait()`, `BtAppEvtNotify()` and `BtAppEvtDispatch()` have been removed; applications should not call `UsbProcess()`.
- nRF52: `BtAppSchedCfg_t` and `g_BtAppSchedCfg` are removed. Replace `app_sched_event_put()` with `AppEvtHandlerQue()` or `BtEvtQue()`.
- `BtAppCfg_t` no longer includes `pEvtHandlerQueMem` or `EvtHandlerQueMemSize`. Applications requiring a larger queue can define `g_AppEvtHandlerQueMem` and initialize the application event queue.
- For RTOS integrations, override `UsbEvtQue()` and `BtEvtQue()` to dispatch work to their subsystem threads, as shown in the TaktOS and FreeRTOS examples.
- `UsbdHidCfg_t` and `UsbIntIntrfCfg_t` require caller-owned, 4-byte-aligned receive and transmit buffers.
- Applications using pairing or bonding call `BtAppSecInit()` during `BtAppInitUserData()`.

## Scope and limitations

Support and hardware coverage differ among MCU families. See [Supported targets](https://github.com/IOsonata/IOsonata/blob/0.13/docs/supported-targets.md) for per-target capabilities. Some MCU ports and peripheral blocks remain at initial bring-up or compile-only status. In particular, nRF54H20 is not yet hardware-qualified, and firmware-update power-loss handling still requires dedicated testing.

This is a release summary; detailed API and example documentation remains in the repository's [documentation index](https://github.com/IOsonata/IOsonata/blob/0.13/docs/index.md).
